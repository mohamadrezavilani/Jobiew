# TajrobeWiki evidence crawler — pilot v0.2 (resilient networking)

هدف: ذخیره نظرات منتشرشده و لینک مرجع برای استخراج شواهد در مرحله بعد؛ **این پروژه فعلاً امتیاز AI تولید نمی‌کند**.

## یافته‌های بررسی وب‌سایت (۱۷ اکتبر ۲۰۲۶)

- مسیر فهرست عمومی: `https://tajrobewiki.com/experiences`
- مسیر نظرات: `/experiences/<slug>`
- فیلترها: `type=work`, `city=تهران`, `industry=کامپیوتر، فناوری اطلاعات و اینترنت`, `page=1`
- صفحات نظر معمولاً عنوان، متن، لینک شرکت، تاریخ، شغل، امتیاز و امتیازهای موضوعی دارند؛ بعضی فیلدها اختیاری‌اند.

## نکات حقوقی و عملیاتی

این بسته **صرفاً برای اجرای مجاز** تهیه شده است. عمومی بودن صفحات یا نبود ممنوعیت صریح در صفحه قوانین، به‌معنی اجازه بازنشر، استفاده تجاری یا کراول خودکار نیست. پیش از اجرا درباره جمع‌آوری و استفاده مجدد از محتوای متعلق به کاربران اجازه معتبر را بررسی/دریافت کنید. در زمان بررسی، `robots.txt` از محیط نویسنده قابل خواندن نبود و بنابراین وضعیت آن تأیید نشده است. کد در زمان اجرا ابتدا آن را می‌خواند؛ اگر ممنوع باشد یا با خطای مبهم روبه‌رو شود متوقف می‌شود. برای فایل robots با وضعیت 404/410 (نبود فایل)، تنها در صورتی جلو می‌رود که کاربر جداگانه تأیید مجوز کرده باشد.

بدون ورود، حل CAPTCHA، تغییر IP، دور زدن محدودیت یا دور زدن HTTP 403/429 کار می‌کند. سرعت درخواست‌ها محدود است (پیش‌فرض ۸ ثانیه + تأخیر تصادفی). پس از HTTP 429/403 متوقف می‌شود.

محتوا را به‌عنوان **ادعای نویسنده** ذخیره کنید، نه واقعیت اثبات‌شده. ممکن است متن حاوی نام اشخاص، داده شخصی یا اتهامات باشد. داده خام را فقط با دسترسی محدود ذخیره کنید و قبل از ارسال به مدل خارجی یا انتشار عمومی، حذف داده‌های شخصی، کنترل مجوز و بازبینی انجام دهید. مطالب منبع ممکن است حذف یا ویرایش شوند و سیاست به‌روزرسانی و حذف لازم است.

## نصب و اجرا در Windows PowerShell

```powershell
cd tajrobewiki_crawler
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v

# فقط دیدن نشانی و محدوده؛ هیچ درخواست شبکه‌ای ارسال نمی‌شود:
python tajrobewiki_crawler.py --dry-run

# فقط پس از تأیید اجازه جمع‌آوری و استفاده از داده:
python tajrobewiki_crawler.py --permission-confirmed --max-pages 2 --max-reviews 20 --pause 12 --retries 1 --retry-wait 30 --max-consecutive-errors 2
```

برای دریافت محدوده بزرگ‌تر بعد از پایلوت:

```powershell
python tajrobewiki_crawler.py --permission-confirmed --max-pages 10 --max-reviews 100 --pause 12 --retries 1
```

برای به‌روزرسانی نظرات قبلی (به جای صرفاً دریافت جدیدها)، از `--refresh` استفاده کنید.

## خروجی

- `data/tajrobewiki.db` — SQLite آزمایشی با جدول `reviews` (ایزوله از DB اصلی محصول)
- `data/reviews.jsonl` — هر خط یک نظر قابل ارجاع و مصرف برای خط لوله LLM
- `data/failed_requests.jsonl` — ثبت URLها و دلایل ناموفق بودن درخواست (برای بررسی بعدی). در اجرای بعد URLهای هنوز ذخیره‌نشده، در صورتی که دوباره در صفحات فهرست حاضر باشند، مجدداً بررسی می‌شوند.
- `url`, `company`, `company_url`, `review_type`, `title`, `body`, `job_title`, `published_jalali`, `employment_period_jalali`, `rating_5`, `dimension_ratings_5`, `pros`, `cons`, `content_sha256`, `crawled_at_utc`.

امتیازهای منبع **فقط داده مرجع** هستند؛ سیستم ما باید مستقل از امتیازهای ویکی‌تجربه شواهد را استخراج و سپس امتیاز خود را محاسبه کند.

## محدودیت‌های نسخه آزمایشی

- CSS/HTML خام سایت از محیط توسعه قابل دریافت نبود؛ پس parser با ساختار *نمایش‌داده‌شده* سایت و fixtureهای مستقل تست شده، ولی **هنوز روی HTML واقعی live تست نشده است**. اگر DOM متفاوت باشد parser خطا می‌دهد و آن نظر را ذخیره نمی‌کند (به‌جای ذخیره محتوای اشتباه). خروجی اجرای واقعی و یک صفحه HTML مجاز برای تطبیق selectorها مفید است.
- بررسی فیلتر هم‌زمان صنعت/شهر/نوع و صحت metadata در HTML واقعی لازم است.
- تشخیص هویت افراد، حذف داده حساس، تشخیص موارد تکرار معنایی و تشخیص زمان واقعی اشتغال جزو مرحله بعد است.
- در صورت تغییر یا حذف نظر از منبع، نسخه MVP فعلاً حذف/تغییر را با زمان‌بندی خودکار پایش نمی‌کند.
- هنگام اجرا هنوز باید اطمینان حاصل شود محدودیت‌های سایت و حجم درخواست‌ها با صاحب منبع توافق شده است.

## نسخه ۰.۲ — رفع توقف ناشی از RemoteDisconnected

لاگ اجرای آزمایشی کاربر (۱۷ اکتبر ۲۰۲۶) نشان داد دو نظر در SQLite ذخیره شدند و سپس `requests.exceptions.ConnectionError` سبب خروج با traceback شد. مشکل اصلی توقف زنجیرهٔ درخواست‌ها هنگام خطای موقت شبکه بود، نه خرابی داده‌های قبلی.

اصلاحات:
- یک بار تلاش مجدد با فاصلهٔ زمانی طولانی‌تر برای `ConnectionError`، `Timeout` و خطاهای HTTP 5xx. با `--retries 0` می‌توان تلاش مجدد را غیرفعال کرد؛ حداکثر مقدار ۲ است.
- HTTP 403 / 429 و عدم اجازه در `robots.txt` توقف کاملِ بدون تلاش مجدد دارند.
- صفحه ناموفق موقت ثبت می‌شود و بعد از چند خطای پشت‌سرهم فرایند با حفظ خروجی‌های قبلی متوقف می‌شود. صفحات 404/410 به‌عنوان حذف‌شده/ناموجود رد می‌شوند.
- هر نظر فوراً در SQLite ثبت می‌شود. اجرای مجدد با DB قبلی باعث حذف یا دریافت مجدد نظرات ذخیره‌شده نمی‌شود (مگر با `--refresh`).
- خروجی JSONL در پایان اجرا حتی پس از پایان زودهنگام ساخته می‌شود.

**مهم هنگام ارتقاء:** پوشه `data` قبلی را حذف یا بازنویسی نکنید. فقط فایل `tajrobewiki_crawler.py` را جایگزین کنید. با `python -m unittest discover -s tests -v` تست‌های آفلاین را بررسی کنید. برای اطمینان از عدم فشار روی سرور، در صورت تداوم قطع اتصال تعداد درخواست‌ها را بیشتر نکنید و وضعیت اجازه استفاده و دسترسی را با مدیر سایت بررسی کنید. تغییر IP یا دورزدن محدودیت سایت راهکار پیشنهادی این بسته نیست.
