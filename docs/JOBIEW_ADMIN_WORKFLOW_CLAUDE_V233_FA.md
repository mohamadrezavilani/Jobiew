# Jobiew v2.0.33 — ادمین خلوت‌تر و مسیر یکپارچهٔ ۶+۶ + بررسی اختیاری Claude

## مهم‌ترین تغییر
در `/admin/` فقط دکمهٔ «میز کار شرکت‌ها» و جست‌وجوی شرکت‌ها در نگاه اول وجود دارد. جدول مدل‌های فنی و تاریخچه زیر بخش بازشوندهٔ «امکانات فنی و تاریخچهٔ حسابرسی» قرار گرفته، اما هیچ مدل، داده، رویداد قبلی یا مجوز Django پاک نشده است.

صفحهٔ شرکت `/admin/companies/company/<id>/workflow/` پنج مرحله را با وضعیت ذخیره‌شده نمایش می‌دهد: (۱) تعداد تجربه‌های واردشده و موجودبودن GPT-6، (۲) بازبینی ۶معیاری و پرونده‌های مانده، (۳) تأیید هویت/فناوری شرکت، (۴) مدارک حقوق منبع و انتساب/استقلال، (۵) انتشار و تعداد قابل نمایش زنده. بالای صفحه **فقط اقدام بعدی** مشخص است؛ لینک‌های جزئی و نقشه در قسمت «تکمیلی» قرار دارند. بازبینی دوبارهٔ ۳۶ امتیاز اسنپ یا تأیید دوبارهٔ موارد تکمیل‌شده لازم نیست. از صفحهٔ فهرست شرکت‌ها نیز فقط دکمهٔ اصلی «ادامهٔ کار» نمایان است و جزئیات بقیهٔ لینک‌ها در بخش بازشونده است.

فهرست تجربه‌های شرکت و صفحهٔ هر تجربه، لینک «بررسی با Claude» و وضعیت نتیجهٔ قبلی را نمایش می‌دهد. از بخش عمومی امتیازها، مقادیر Claude یا متن خام مدل نمایش داده نمی‌شوند.

## تفاوت Claude ۶+۶ با نسخهٔ تاریخی
Claude قبلی `assessments.AiAssessment(five_v1)` عمداً متوقف است و امتیازهای آن در GPT-6 وارد نمی‌شود. در این تغییر جدول مستقل `criteria_v2.CriteriaClaudeComparison` ساخته می‌شود. این ابزار فقط برای تحلیل خصوصی GPT-6 موجود (نوع کاری یا مصاحبه) است:
- بازکردن صفحهٔ Claude **هیچ API فراخوانی نمی‌کند**؛ نتیجهٔ قبلی، زمان، مدل و مقایسهٔ شش محور نشان داده می‌شود.
- **پیش‌فرض اجرای پولی خاموش است.** برای فعال‌سازی آگاهانه پس از بررسی هزینه و حق استفاده از داده‌ها: `JOBIEW_CLAUDE_SIX_ENABLED=1`، `JOBIEW_CLAUDE_SIX_LIMIT=4` (سهمیهٔ کلی) و `ANTHROPIC_API_KEY` معتبر نیاز است. مدل به‌طور پیش‌فرض `claude-sonnet-5-5` است و با `JOBIEW_CLAUDE_SIX_MODEL` قابل تنظیم. در نسخهٔ پیش‌فرض پروژه، هیچ فراخوانی هزینه‌داری انجام نمی‌شود.
- ارسال یک تجربه به سرویس بیرونی فقط با وجود رویداد تأیید حقوق منبع و دو تأیید صریحِ بازبین (مجوز پردازش بیرونی + آگاهی از هزینه) و سطح دسترسی `criteria_v2.add_criteriaclaudecomparison` امکان‌پذیر است. «مجوز بازنشر در جابیو» **لزوماً** مجوز ارسال به Anthropic نیست؛ بازبین باید شمول مدرک را مستقلاً بررسی کند. اطلاعات آشکار تماس‌ها با best-effort حذف می‌شود، اما حذف تضمینی همهٔ PII نیست.
- برای هر تحلیل فقط یک درخواست مدل مجاز است. خطای شبکه یا خروجی ناقص نتیجهٔ `failed` می‌سازد و **تلاش مجدد خودکار ندارد**؛ تغییر آن نیازمند گردش کار کنترل‌شدهٔ جداگانه است. این تصمیم از دوبار هزینه شدن ناخواسته جلوگیری می‌کند.
- پاسخ Claude با schema مستقل شش‌معیاری و شاهد لفظ‌به‌لفظ از روایت اعتبارسنجی می‌شود، سپس نتیجهٔ شش محور و اختلاف با GPT-6 فقط در ادمین ذخیره/نمایش داده می‌شود. این مقایسه **امتیاز GPT-6، رویداد بازبینی، مجوز منبع یا تصمیم انتشار را تغییر نمی‌دهد**. اگر نسخهٔ منبع عوض شود، نتیجهٔ تاریخی دوباره به‌عنوان «نتیجهٔ فعلی» نمایش داده نمی‌شود.

## آنچه این فاز عمداً تغییر نداده
ورود بسته‌های بزرگ تجربه/نتایج GPT-6 هنوز از management command کنترل‌شده انجام می‌شود؛ فرم آپلود عمومی ZIP یا صدور خودکار مجوز منبع ایجاد نشده است. برای آماده‌سازی ورود نظرات بعدی می‌توان یک صفحهٔ امنِ پیش‌نمایش import با خطایابی و تأیید نهایی ساخت، اما ساخت آن نیازمند طراحی جداگانهٔ قالب بسته و جلوگیری از duplicate/شکستن رسیدهای قبلی است. در فاز حاضر فقط رابط و گردش کارِ تجربه‌های **موجود** کوتاه شده‌اند.

## استقرار و کنترل
مهاجرت جدید `criteria_v2.0006_criteriaclaudecomparison_v233` است و قبل از راه‌اندازی صفحهٔ Claude باید با `manage.py migrate --noinput` روی سرور اجرا شود. بعد از آن `manage.py check`، `collectstatic --noinput` و `jobiew-web` restart. این migration فقط جدول خالی مقایسهٔ Claude را اضافه می‌کند؛ به ۲٬۲۳۴ checkpoint، تأییدهای شیپور/اسنپ یا تصمیم انتشار دست نمی‌زند.
