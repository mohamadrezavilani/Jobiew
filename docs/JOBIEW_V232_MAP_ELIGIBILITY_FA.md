# Jobiew v2.0.32 — توضیح دقیق اینکه چرا مکان تأییدشده در نقشه نیست

## مشکل مشاهده‌شده
کاربر پس از انتشار ۳۴ امتیاز اسنپ و تأیید موقعیت دفتر، در صفحهٔ اصلی پیام «موقعیت تأییدشده‌ای در این صفحه وجود ندارد» دید. مسیر امتیازها و مکان مستقل‌اند. خروجی سرور `RELEASE=published, RECORDED=34, VISIBLE=34, GATES=True` فقط نمایش امتیازهای ۶+۶ را تأیید می‌کند، نه موجود بودن مکان تأییدشده در GeoJSON.

## قواعد واقعی نمایش پین
نقشهٔ عمومی `/map/` و صفحهٔ نخست `/api/locations.geojson` را استفاده می‌کنند. شرایط در تابع مشترک `companies.map_visibility_v232.verified_company_locations()` نگهداری شده و عیناً در پنل بررسی شرکت اعمال می‌شود:
- هویت شرکت `verified`
- فناوری بودن `verified`
- **ارتباط با تهران `tehran_status=verified` (مستقل از دو تأیید بالا)**
- وجود رکورد مکان با `verification_status=verified`، `verified_at`، عرض/طول و لینک مدرک
- وجود رویداد اخیر `CompanyLocationReviewEvent` با تصمیم `verified` و **مختصات و مدرک کاملاً مطابق با رکورد فعلی** (از تزریق دستی یا تصمیم‌های ابطال‌شده جلوگیری می‌شود).

«هویت و فناوری تأیید شد» (فرم سریع شرکت)، «بازبینی امتیازهای GPT-6»، و «انتشار امتیازها» به تنهایی مجوز پین نمی‌دهند. این سند دربارهٔ سرور واقعی وضعیت تأیید تهران اسنپ را حدس نمی‌زند.

## تجربهٔ جدید ادمین
در `/admin/companies/company/<id>/review/#map-visibility` اکنون چک‌لیست مستقل و **پایدار** ۶ شرط نمایش نقشه با وضعیت «تأییدشده/ناقص»، جزئیات و لینک همان فیلد دیده می‌شود. بالای پنل نتیجهٔ واقعی وجود/عدم وجود پین در **همان queryset رسمی GeoJSON** گزارش می‌شود. مقادیر از دیتابیس خوانده می‌شوند و پس از خروج و ورود نیز صحیح خواهند بود؛ هیچ بررسی خودکار ثبت نمی‌شود.
از صفحهٔ `/admin/companies/company/<id>/checkpoint/release/` نیز وضعیت مستقل مکان و فهرست شرایط ناقص به صفحهٔ بررسی شرکت لینک داده شده است. بدین ترتیب انتشار موفق ۳۴ امتیاز با انتشار مکان اشتباه گرفته نمی‌شود.

## تفاوت نقشهٔ صفحهٔ اصلی و نقشهٔ مستقل
نقشهٔ صفحهٔ اصلی تنها پین شرکت‌های **در حال حاضر موجود در فهرست صفحهٔ اول** را نشان می‌دهد؛ بنابراین فیلتر، جست‌وجو و صفحه‌بندی ممکن است یک پینِ معتبر در سایت را مخفی کنند. نقشهٔ مستقل `/map/` تمام پین‌های تأییدشده را از همان API دریافت می‌کند. برای تست اسنپ بهتر است با `/?q=اسنپ` فهرست را محدود کنید، سپس `/map/` را مقایسه کنید. هیچ مختصات جغرافیایی برای شرکت به صورت فرضی تولید نشده است.

## بررسی امن روی سرور بدون نوشتن اطلاعات
در `/opt/jobiew/backend` با env محیطی `/etc/jobiew/jobiew.env`:

```bash
sudo systemd-run --unit="jobiew-snapp-map-audit-$(date +%s)" --wait --pipe --collect \
  --uid=jobiew --property=EnvironmentFile=/etc/jobiew/jobiew.env \
  --working-directory=/opt/jobiew/backend \
  /opt/jobiew/.venv/bin/python manage.py shell -c '
from companies.models import Company
from companies.map_visibility_v232 import company_map_status
c=Company.objects.get(pk="c8a19a54a6e76f538acee")
s=company_map_status(c)
print("PUBLIC_MAP_PIN:", s["visible"])
for item in s["checks"]:
    print(item["code"], "OK" if item["ok"] else "MISSING", item["details"])
'
```

اگر `tehran=MISSING` باشد، به صفحهٔ بررسی شرکت برو و فقط در صورت داشتن مدرک معتبر، تصمیم «ارتباط با تهران» را ثبت کن. اگر `latest_review=MISSING` باشد، نشانی و مختصات را با سند معتبر در بخش مکان دفتر بررسی و تأیید کن؛ اطلاعات سابق قابل حفظ است اما رویداد جدید append-only نیاز است. در صورت `PUBLIC_MAP_PIN: True` اما نبود روی صفحهٔ اول، صفحه‌بندی/فیلتر را بررسی کن. اگر خروجی API با پنل ناسازگار بود، بدون ساختن مکان ساختگی کد/کش را بررسی کن.

## آزمون
تست‌های Django شبیه‌سازی می‌کنند مکان تأییدشده اما تهران تأییدنشده باشد (پین نباید نمایش یابد)، بعد تهران تأیید شود (باید پین ظاهر شود)، و بعدها تغییر مستقیم مختصات باعث مسدودشدن مکان شود (هم در API و هم در چک‌لیست پنل). تست انتشـار امتیاز بدون مکان هم تضمین می‌کند تعداد نمرهٔ GPT-6 با وضعیت نقشه اشتباه گرفته نشود. migration جدید یا تغییر در امتیازها و تصمیم‌های قدیمی وجود ندارد.
