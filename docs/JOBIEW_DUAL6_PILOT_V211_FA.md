# Jobiew v2.0.11 — نمونه‌گیری کور، برچسب مرجع انسانی و ممیزی کیفیت

هدف: اندازه‌گیری کیفیت واقعی تحلیل مستقل ۶ معیار کاری و ۶ معیار مصاحبه، بدون انتشار نمره، بدون درخواست پولی، و بدون انتقال متن منبع به GitHub.

## آنچه اصلاح شد

در ابزار v2.0.10، یک نمرهٔ دارای نقل‌قول ساختگی، یا خروجی با تشخیص نوع غلط، صرفاً «خطادار» شمرده می‌شد اما می‌توانست به نسبت نمرات توافقی/MAE کمک کند. در v2.0.11 این نمرات از صورت موفقیت خارج می‌شوند ولی به‌عنوان تلاش برای امتیازدهی در مخرج precision می‌مانند. گزارش کیفیت همچنان آماری توصیفی است و مجوز انتشار نمی‌دهد.

## آماده‌سازی نمونهٔ خصوصی از دیتابیس **محلی ویندوز**

فرمان `export_dual6_pilot_v211` صرفاً خواندنی است. فقط روی Windows اجرا می‌شود و اتصال دیتابیس غیرمحلی را رد می‌کند. هیچ درخواست AI ندارد و هیچ Migration یا ذخیره‌ای در DB انجام نمی‌دهد. پوشهٔ خروجی باید **خارج از مخزن Git** و از قبل ناموجود باشد.

برای فعال شدن Django، متغیرهای محیطی توسعه و PostgreSQL محلی باید طبق تنظیمات موجود Jobiew آماده باشند (`DJANGO_DEBUG=1` و `data/postgres_local.json` یا `WI_DB_*`). سپس از ریشه پروژه:

```powershell
$env:DJANGO_SETTINGS_MODULE='workplace_insights.settings'
$env:DJANGO_DEBUG='1'
$env:DJANGO_SECRET_KEY='local-pilot-not-for-production'
$env:WI_DB_ENGINE='postgresql'
$env:PYTHONPATH="$($PWD.Path)\backend"
python backend/manage.py export_dual6_pilot_v211 --output-dir "C:\jobiew-private\pilot-v211" --per-kind 20 --acknowledge-private-export
```

به‌طور پیش‌فرض فقط متن‌هایی انتخاب می‌شوند که بررسی حقوق استفاده از آنها `approved` باشد. اگر برای تحلیل داخلیِ محرمانه اجازه بررسی موارد pending وجود دارد، تنها پس از بررسی حقوقی و به‌صورت اختیاری از `--include-pending-copyright` استفاده شود. این گزینه به‌هیچ‌وجه مجوز ارسال متن به API بیرونی یا انتشار نیست. رکوردهای مسدود، انتساب‌ردشده و تکراری حذف می‌شوند.

خروجی‌های محلی و خصوصی:

- `stories.json`: متن‌های خصوصی پاک‌سازی اولیه‌شده در گروه‌های کار و مصاحبه؛ پاک‌سازی به معنی ناشناس‌سازی تضمین‌شده نیست.
- `gold_template.json`: شش معیار و خانهٔ `HUMAN_LABEL_REQUIRED` برای هر معیار، **بدون پیش‌بینی مدل**.
- `predictions_template.json`: پیش‌بینی‌های خالی (`null`)؛ تنها بعداً با خروجی واقعی مدل پر می‌شوند.
- `mapping_private.json`: نگاشت شناسهٔ آزمایشی به شناسهٔ داخلی تجربه؛ فقط برای بازبینی داخلی.

همهٔ این فایل‌ها خارج از Git و محرمانه‌اند. هیچ کدام را Push یا به این گفتگو آپلود نکنید. در صورت نیاز فقط گزارش تجمیعی نهاییِ فاقد متن خام را به اشتراک بگذارید.

## دستور کار ارزیابی

۱. بازبین انسانی **بدون دیدن پیش‌بینی** هر شش بُعد را با `score` عدد ۱ تا ۱۰ یا `null` و `evidence` عین متن علامت بزند؛ در حالت `null` شاهد باید خالی باشد. فقط اشارهٔ اسمی به موضوع برای نمره کافی نیست.

۲. برای کنترل سازگاری انسانی، حداقل بخشی از موارد را دو بازبین مستقل برچسب بزنند و اختلاف‌ها را پیش از نمره‌دهی به مدل حل کنند. نمونه باید موارد مثبت، منفی، متناقض، مبهم و بدون شاهد را شامل شود. دسته‌بندی طول متن در ابزار نمونه‌گیری صرفاً برای پوشش طول است، نه تضمین نمایندگی معنایی.

۳. پیش‌بینی‌های واقعیِ همان متن‌ها (با شش کلید درست و نسخهٔ مشخص) را در `predictions_template.json` وارد کنید. این مرحله هیچ مدلی را صدا نمی‌زند. هر اجرای پولی و ارسال متن به ارائه‌دهندهٔ بیرونی مجوز صریح جداگانه می‌خواهد.

۴. با فایل‌های برچسب‌خورده، گزارش تجمیعی امن بسازید:

```powershell
$env:PYTHONPATH="$($PWD.Path)\backend"
python -m criteria_v2.pilot_v211 assemble --stories "C:\jobiew-private\pilot-v211\stories.json" --gold "C:\jobiew-private\pilot-v211\gold_template.json" --predictions "C:\jobiew-private\pilot-v211\predictions_template.json" --report "C:\jobiew-private\pilot-v211\quality_report.json"
```

این ابزار تا کامل‌شدن همهٔ برچسب‌های انسانی و پیش‌بینی‌های واقعی، با خطای صریح متوقف می‌شود. گزارش خروجی شامل متن خام نیست و `release_approved=false` باقی می‌ماند.

## قرارداد محصولی

کفایت داده مستقل از کیفیت مدل است. طبق مستند MVP: برای هر بُعد ۰ تجربهٔ مرتبط = بدون امتیاز؛ ۱ تا ۵ = اطلاعات ناقص با نمرهٔ معتبر؛ ۶ یا بیشتر = کافی. همین قاعده برای کاری/مصاحبه مستقل است و هیچ‌یک به معنی استقلال واقعی نویسندگان یا اعتبار آماری نیست. فرمول میانگین ساده هنوز موقتی است و برای انتشار باید جدا تأیید شود.
